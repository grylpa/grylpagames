# Aliens — Design Doc

## Overview

Cute little aliens roam an open field. There are 1–2 **target areas**, each drawn as two
concentric circles: an **outer ring** (annulus) and an **inner ring** (inner disc). Each area
has a rule about alien traits ("3 EYES", "TALL", "BLUE").

Aliens walk into an area's **outer ring by themselves** and park there. They can never enter an
inner ring on their own. The player drags each arrival either **into the inner ring** (if it
matches that area's rule) or **back out to the field** (if it doesn't). While an outer ring is
full, aliens that walk up to it are turned away and each one costs a miss.

Successor to `rlmadness` (same rapid rule-switching under interference, arcade presentation).
`rlmadness` remains commented out of `scripts/config.gd`.

Aliens are **drawn**, not images — no per-game art beyond the chooser thumbnail.

## Trait model

Six **independent** dimensions, heaviest visual weight first. Independence is the entire
confusion mechanism — traits must never be correlated.

| dim | field | values |
|---|---|---|
| body color | `color_id` | 0 blue, 1 red, 2 green, 3 yellow, 4 purple |
| height | `is_tall` | TALL = **taller than it is wide**, SHORT = **wider than it is tall** |
| girth | `is_fat` | WIDE / NARROW (body ellipse `rx`) |
| eyes | `eyes` | 1 / 2 / 3 |
| antennae | `antennae` | 0 / 1 / 2 |
| spots | `has_spots` | bool (lower body only) |

Mouth is deliberately **not** a trait — every alien wears the same smile (cuteness, zero
information). It would be the weakest discriminator at phone size and it competes with the eyes
for face area.

**TALL is defined so both readings agree.** A tall alien is taller than it is wide at *either*
girth, and a short one is wider than it is tall. Previously "tall" meant only greater absolute
height, so a tall+wide alien came out `(0.92 w, 0.86 h)` — visibly wider than tall while labelled
TALL, judgeable only by comparing it against other aliens. Girth stays independent: height sets
`ry`, girth sets `rx`. Nothing exceeds `radius`, so the body always fits the collision circle.

**Eyes are drawn as three distinct SHAPES, not three counts**: 1 = one big central eye,
2 = a horizontal pair, 3 = a triangle. Recognizing a shape is instant; counting pips is not. The
triangle also fits a narrow body, where a row of three would have to shrink to nothing.

17 rule keys, all evaluated by one `_alien_matches(al, rule_key)` match statement. See the
comment block at the top of `level_config.gd` for the authoritative list with labels.

## Rules

- **No confusability table is needed** (unlike sortingrobots/monkeyc). An alien is judged only
  against the rule of the area it walked into, so an alien matching both areas' rules is
  harmless — it belongs wherever it went.
- **Usability filter** (`_is_rule_usable`): a rule is only offered if the level's trait pools can
  produce both matches and non-matches. Pools may safely over-list; unusable keys are dropped.
- **`COMPLEMENTS`**: two areas never get an exact complement pair (`tall/short`, `fat/thin`,
  `spots/nospots`) — that would collapse two independent judgments into one binary. Two
  *different values of the same dimension* (BLUE vs RED, 2 EYES vs 3 EYES) are fine and good.
- **Arrival mix ~50/50**, kept there by two light mechanisms rather than a scheduler:
  `_choose_area_for` sends an alien to an area it actually fits about half the time
  (`SMART_ENTRY`), and `_arrival_allowed` softly vetoes an attempt when the last 8 arrivals were
  already lopsided (`ARRIVAL_WINDOW` / `ARRIVAL_SKEW`). Never a hard block. Without this, on a
  rule matching only a third of aliens most walk-ins would be mismatches and "always push it out"
  would be a winning strategy. Measured 0.479 over 142 real self-initiated arrivals.
- **Hiding**: after `hide_after_sec` the chip reads `?` — not blank, so the player still knows
  *that* there is a rule; the load is recalling *which*. `0` = never hide.

## Geometry — why parked aliens can never overlap

All radii derive from the alien radius `a`, so it is correct by construction:

```
r_in  = a * SLOT_GAP / sin(PI/k_in) + a * INNER_MARGIN     (k_in > 1)
r_out = r_in + a * BAND_MUL                                 (BAND_MUL 2.30, 2.0 = exact fit)
s_out = (r_in + r_out) * 0.5     s_in = a * SLOT_GAP / sin(PI/k_in)
```


Slot angles carry a **`+PI/k` offset** so there is a gap at 12 o'clock, directly under the rule
chip — a parked alien is never hidden by its own label.

**Every alien has the same collision `radius`** regardless of shape. This is load-bearing: slot
spacing, separation, band width and keep-out all become one constant. A slim alien just has air
around it. Do not make the radius shape-dependent.

## Roaming and non-overlap

State machine (`AState`): `ROAM / SEEKING_SLOT / PARKED_OUTER / PARKED_INNER / LEAVING /
DRAGGED / SNAPPING / FADING`.

- `sim_pos` is authoritative and is copied to `position` **once** per frame — the solver runs
  several passes and must not dirty the node transform on each.
- **`_resolve_positions()` INTERLEAVES separation and ring keep-out** (`RESOLVE_CYCLES = 4`, each
  with `SEP_ITERS = 3`). Running them once each is **not enough**: keep-out shoves an alien into
  a neighbor with no chance to re-resolve, which measurably left aliens overlapping by ~0.6 px on
  the crowded level 8. Alternating lets each constraint fix what the other broke, and ending on
  keep-out guarantees no roamer is left inside a ring.
- The wall bounce is **idempotent** (flip only when actually pressing outward) because it runs
  once per resolve cycle; a plain "flip if out of bounds" would flip an even number of times and
  send the alien back into the wall.
- **Every alien wants in.** There is NO global entry scheduler. On each retarget (~1-2 s) a ROAM
  alien rolls `enter_chance` and, if it hits, commits to an area and walks in (`_try_enter`).
  `MIN_ENTRY_GAP_MS` only stops two committing on the very same frame.
- Between commits an alien picks its wander target in a **loitering band** just outside a random
  ring (`LOITER_BIAS`, `LOITER_BAND`), so the crowd reads as "queueing up" rather than drifting
  at random. This concentrates the population near the areas, which is why the solver needs more
  passes than a uniformly spread field would.
- Wander targets are rejection-sampled outside every disk, so an alien never *steers* into a ring.
- **Aliens never walk over an INNER ring.** `_push_out_of_areas` keeps everyone out of the whole
  disc except in their own area, where they are still kept out of the inner disc (`INNER_PAD`).
  The only way into an inner ring is the player dragging an alien there.
- **Wedge escape.** A band between a ring and a screen edge can be narrower than an alien, and the
  field clamp undoes the radial keep-out every frame — a permanent trap. `_slide_out_of_wedge`
  moves such an alien *along* the ring toward the open middle, and a pinched alien is also
  retargeted at the field centre so it walks itself free instead of being shoved back.
- A seeker that cannot squeeze into a crowded ring gives up after `SEEK_TIMEOUT_MS` (3.5 s) and
  visibly wanders off **away from that ring**, which reads as changing its mind rather than being
  stuck. Standing still for 6 s looked like a bug even though the watchdog would have freed it.
- A seeker walks to a **gate** radially outside its own slot, then straight in along that radius —
  never diagonally across the annulus, so it cannot brush a parked neighbor. It claims the
  **nearest** free slot and heads for the **nearest** acceptable area; a cross-field hike gets
  deflected around the other ring and takes many seconds, which reads as being stuck.
- `_steer` has **arrival slowdown** (`ARRIVE_RADIUS_MUL`). Without it the velocity lerp needed
  ~12 frames to turn — further than the arrival tolerance — so a seeker sailed past its waypoint
  and **orbited it forever at full speed**. The gate leg also counts as reached once the alien is
  merely NEAR the ring: requiring a pinpoint arrival let it slide around at the right radius and
  the wrong angle indefinitely.
- `SEEK_TIMEOUT_MS` is a watchdog: any approach that somehow still fails to complete is abandoned
  with **no penalty** and the alien re-roams. Geometry bugs can therefore never wedge an alien
  permanently.

## Population supply

The roaming pool must always hold aliens that MATCH each area's rule and aliens that don't, or the
game runs dry: with rule BLUE, once the blue ones have been promoted and recycled to random colors
there is no correct answer left to give and every arrival becomes an eviction.

- `_find_supply_gap` reports the first side of any area that has fewer than `MIN_SUPPLY` roamers.
- `_top_up_supply` (every `TOPUP_PERIOD_MS`, up to `TOPUP_MAX_PER_TICK` swaps) fills gaps by
  **converting a surplus roamer**: it fades out and returns with `_force_rule` nudging only the
  ONE deciding trait, so every other dimension stays an independent random draw and the confusion
  is preserved. Swaps are deliberately slow (`TOPUP_PERIOD_MS` 1.2 s, max 2) and fade both out AND
  in (`fade_in_t0`) — fast popping in and out was very visible. Measured 0.1–0.3 swaps/s.
- Victim choice is three-tier: a roamer that `_can_spare` (converting it won't open another gap —
  two rules can read the same dimension, e.g. BLUE and RED, so a naive swap oscillates), else any
  other-class roamer, else **spawn a new alien**. Spawning is the last resort because it inflates
  the field beyond `num_free_aliens`; `_recycle` retires surplus aliens once the pool is stocked,
  so the population settles back. `SUPPLY_HEADROOM` caps the growth.
- `_find_supply_gap` counts aliens that are **in play** (ROAM, SEEKING_SLOT or PARKED_OUTER), not
  just roamers. Counting roamers alone meant that when the rings filled up the pool looked
  permanently short, so it kept spawning until the field was overcrowded and aliens jammed.
- `_stock_initial_supply` guarantees the opening population holds both answers rather than
  trusting the dice.
- `_random_free_point(r, avoid_aliens)` must be used for respawns — placing an alien on top of a
  neighbor is an instant overlap the solver then has to unpick, and with frequent top-ups it was
  visible.

## Feedback and captions

- **Every judgment is unmissable**: `_flash_mark` floats a large ✓ +N / ✗ -N (outlined, ~2.1×
  the alien radius) up from the alien and fades it, alongside a colored ring flash on the alien
  itself. The small hint ring alone was too subtle to tell a correct call from a mistake.
  A turned-away alien flashes `FULL!`.
- **No on-screen instruction line.** The intro popup covers the rules; a permanent caption over
  the play area was just distraction. The inner-ring slot pips were removed for the same reason —
  they marked where a promoted alien would land, which the alien itself makes obvious.
- **Rule captions live in reserved bands** at the top and bottom of the field — a top-corner area
  captions in the top band, a bottom-corner one in the bottom band — so a caption never sits over
  a ring or over the roaming aliens. They are deliberately quiet (no border, faint backdrop).
- `label_res` is derived from the **font metrics** (`get_height(cap_fs) + 18`), not a constant. A
  Control's size is clamped to its content minimum, so a fixed 26px band silently held a 44px
  label that spilled over the ring and off the field. `clip_text` plus `_fit_caption` keep the
  width in range too.
- When the rules hide, the caption is **removed** (`visible = false`), not replaced by a `?`
  placeholder — an empty box left on screen is just clutter.

## Pressure and level flow

- Outer ring availability is re-checked **every frame** during the walk; the miss is only booked
  when the alien reaches the gate. That turns a flat punishment into a skill window ("free a slot
  before it gets there"). Verified both ways.
- `enter_chance` is the arrival-rate knob (0.16 on level 1 → 0.60 on level 8).
- **`RE_ENTRY_COOLDOWN_MS`**: an alien pushed out (or one that gave up, or was turned away) is sent
  walking away from that ring via `_send_away_from` and cannot try to enter again for 5 s. Without
  it a released alien turned straight round and marched back in, which made a *correct* release
  look like a failed drag.
- `park_patience_sec` is the deadlock valve: a parked alien the player never resolves leaves on
  its own with **no** penalty. `0` disables it (levels 7–8, where the pressure is the point).
- A promoted alien celebrates in the inner ring for `INNER_HOLD_MS`, fades, and is **recycled**
  with fresh traits elsewhere. Keeps `inner_slots` small, the population constant, the mix fresh.
- Level ends when `level_time_sec` elapses (`game.sig_time_over` → `_level_done`). Accuracy feeds
  `AliensG.record_level_result` → replay if under 70%.
- `main.gd` sets `game.game_over_on_time_out = false`: the clock is a per-level budget.

## Scoring

| event | score | counted |
|---|---|---|
| correct promote / correct release | `+12 + speed bonus` (max +10) | `corrects+1`, round |
| MISTAKE (bad promotion, evicted a match) — the move still commits | `-min(4, score)` | `mistakes+1`, round |
| turned away at a FULL ring | `-min(2, score)` | `mistakes+1`, round |
| ILLEGAL drop | nothing | not counted |

**ILLEGAL vs MISTAKE is the key distinction.** Illegal = a move the rules don't permit (field →
any ring; another area's ring → this inner ring). It is an affordance error, refused silently and
free of charge. Mistake = a legal move with the wrong judgment. Only mistakes are scored against
the player.

**Response time** is measured from the alien **parking in the outer ring** to the player
**grabbing it** — the decision time. It deliberately excludes the drag itself, which is hand speed
rather than thinking, and it is banked in `grab_delay_ms` at `_begin_drag` so a slow drag cannot
inflate it. Only **correct** calls are recorded: a mistake, an illegal move, or repositioning a
roaming alien record nothing. The speed bonus uses the same value.

With no correct call at all the average would come out 0 — which reads as *perfect* on a
lower-is-better metric — so `mean_response_time_ms()` returns `NO_ANSWER_MS` (99999) instead. The
level-done popup still shows "N/A" in that case; it is the stored score row that carries the
large value.

Score row: `[..., didwin, wasaborted, level_id, mean_ms, pct]` →
`POS_SCORE_LEVEL_ID = 6`, `MEAN_TIME_MS = 7`, `PCT_CORRECT = 8`.

## Drag legality

Resolved from the alien's **center** at release (`_region_at`), so there is no straddling.

| origin | drop region | outcome |
|---|---|---|
| PARKED_OUTER(H) | INNER(H), match | **correct** → promote |
| PARKED_OUTER(H) | INNER(H), mismatch | **mistake**, but it still goes in |
| PARKED_OUTER(H) | FIELD, mismatch | **correct** → release to ROAM |
| PARKED_OUTER(H) | FIELD, match | **mistake**, but it is still released |
| PARKED_OUTER(H) | OUTER(H) | silent no-op → snap to slot |
| PARKED_OUTER(H) | any region of area J≠H | **illegal**, no score → snap back |
| ROAM | FIELD | reposition, no score |
| ROAM | INNER or OUTER (any) | **illegal**, no score → snap back |
| PARKED_INNER / SNAPPING / FADING | — | not grabbable |

**A MISTAKE is scored but still CARRIED OUT** — the alien goes where the player put it, with a
500 ms red flash (`_flash_hint` / `HINT_FLASH_MS`, self-clearing) so the error is legible.
Springing it back read as the game refusing the gesture rather than judging it. Only an
**ILLEGAL** move (one the rules do not permit) snaps back, because there is no valid outcome to
commit to.

Snap-back is **manual, not a Tween**, so separation (which treats SNAPPING as immovable) can
never fight the animation. The drag hint shows only whether the drop would be *accepted* — it
never leaks whether the alien matches the rule.

## Layout

Areas sit in the screen **CORNERS** (`CORNER_SIGNS`, order TL → BR → TR → BL): one area centres in
the field, two take **opposing** corners, three or four fill the rest. Corners keep the middle of
the field open as one contiguous roaming space and put the two rings as far apart as possible.

`alien_size` → `sw * base_frac * 0.5` (big .112 / med .098 / small .086), `×0.70` off mobile —
the same platform-independent convention as `change`. The radius is then shrunk in an 8-step loop
until the rings fit, a real meadow exists (`>= 4.4a` tall) and there is area for every roamer.

Measured on 680×788 mobile: levels 1–2 `a=38.1` (~121 device px diameter), 3–6 `a=33.3` (~106),
7–8 `a=29.2` (~93). No level needed the shrink loop.

## Key Pitfalls

- **Never run separation and keep-out once each** — see `_resolve_positions()` above.
- `_constrain_alien` must NOT commit `position`; the commit is a single pass in `_process`.
- Only `SEEKING_SLOT` / `PARKED_*` / `LEAVING` aliens may be inside a disk, and only inside
  **their own** (`skip_idx`). Everything else is projected out of every disk.
- A **reservation counts as occupied** (`_reserve_park` writes the angle immediately, and
  `_taken_angles` includes walking seekers) — that is what stops two seekers claiming one spot. A
  grabbed seeker must `_release_park`.
- `_build_modality`-style per-instance randomness does not exist here, but `_roll_traits` must
  keep the six dimensions **independent**; correlating any two silently destroys the confusion.
- The chooser `load()`s `art/game_screen_200.png` unconditionally — it must exist.

## Verification

No CLI test pipeline. `aliens/scenes/zz_probe.{gd,tscn}` was a temporary probe (deleted after
use) asserting: ring geometry for all 8 levels × 1–2 areas; mobile radius convergence; 3600
simulation steps with no overlap (min gap ≈ 2.0 px), no roamer inside a ring, slot ownership a
bijection, constant population; both pressure paths; the full 8-row drag legality matrix
including the cross-area illegal case; a REAL press→move→release through `_on_catcher_gui_input`
asserting the alien tracks the pointer and scores on release; self-entry (aliens reach the rings
with no scheduler); rule key validity, distinctness, non-complement pairs, base rates in range,
arrival mix ≈ 0.5 over real arrivals, and trait independence `|P(tall|eyes3) − P(tall)| < 0.06`.

**The probe must drive `_simulate()`, never a hand-copied frame loop.** An earlier probe
mirrored `_process` by hand, drifted out of sync, and silently never ran the supply top-up — so
the supply system looked broken when it was simply not being called. `_process` now only gates
and clamps; all per-frame work lives in `_simulate(d, now)`.

**Do not let a probe set `_drag_alien` by hand** — an earlier version did, and it masked a real
bug where `_begin_drag` never assigned it, so in the actual game the alien froze under the finger
instead of following it. Drive `_on_catcher_gui_input` end to end.

Re-create it from this list if the simulation is changed.
